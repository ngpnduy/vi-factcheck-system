# Baseline M0 — ViFactCheck

## Mục tiêu và trạng thái

M0 đã có pipeline chuẩn bị dữ liệu, retrieval, train, lưu/nạp checkpoint, predict và evaluation. Luồng mô hình:

```text
claim + context riêng của claim
    → tách context thành câu nguyên văn có offset
    → BM25 trên các câu trong context đó (top-20 được lưu)
    → lấy top-5, hoặc tất cả nếu context có ít hơn 5 câu
    → VnCoreNLP tách từ cho claim và từng câu
    → PhoBERT phân loại từng cặp claim–câu
    → trung bình xác suất ba nhãn của các câu thật
    → nhãn có xác suất cao nhất
```

Công thức: `P(y | claim) = (1/n) Σ softmax(logits_i)[y]`; loss của claim là `-log P(gold_label | claim)`. Trainer tính loss trung bình theo claim, kể cả batch/nhóm gradient accumulation cuối có ít mẫu hơn. Không lấy trung bình logits, không nối tất cả evidence thành một đầu vào, không gán nhãn claim cho từng câu để tính loss độc lập.

**Trạng thái thực nghiệm hiện tại:** development. Đã chạy smoke test bằng PhoBERT thật trên 16 claim train và 12 claim validation, lưu/nạp checkpoint cho xác suất giống nhau. Đã chuẩn bị đủ 5.062 train và 723 validation. Checkpoint smoke cũng đã chạy inference qua đủ 723 claim validation để kiểm tra không bỏ sót mẫu. Chưa huấn luyện toàn bộ train trong 5 epoch hoặc chạy đủ 3 seed; checkpoint smoke không phải mô hình dùng để báo cáo kết quả baseline chính thức.

Learning rate `2e-5` hiện là giá trị thử nghiệm. Theo Proposal, learning rate chung phải được chọn bằng M1 trên validation trước bảng so sánh cuối. Bộ tách câu `conservative_vi_v1` cũng cần rà soát pilot trước khi khóa giao thức. Không sử dụng test để chỉnh cấu hình.

## Môi trường

- Python và dependencies theo `uv.lock`: chạy `bash scripts/setup.sh` trên máy mới.
- Java **11 trở lên** để chạy VnCoreNLP qua source-file launcher. Kiểm tra bằng `java -version`.
- CPU chạy được smoke test; nên dùng GPU cho huấn luyện đủ dữ liệu. `device: auto` ưu tiên CUDA, rồi MPS, rồi CPU. Môi trường kiểm tra hiện chỉ nhận CPU.
- Không cần thêm package Python tách từ. Bridge gọi tài nguyên VnCoreNLP chính thức, kiểm tra checksum và chạy một Java process trong suốt phiên train/predict.
- Tài nguyên tải về nằm trong `outputs/models/` và không được đưa vào Git. Bridge tạo bản tạm ở đường dẫn ASCII để tránh lỗi upstream VnCoreNLP với dấu tiếng Việt/khoảng trắng trong đường dẫn.

Nguồn kỹ thuật: [PhoBERT model card](https://huggingface.co/vinai/phobert-base-v2) yêu cầu tách từ trước khi dùng tokenizer và khuyến nghị RDRSegmenter/VnCoreNLP. [VnCoreNLP](https://github.com/vncorenlp/VnCoreNLP) cung cấp bộ `wseg`. Mã tải tài nguyên cố định commit của cả hai nguồn; huấn luyện và dự đoán dùng tài nguyên cục bộ, không tự tải model mới.

## Chạy lần đầu

Chạy các lệnh từ thư mục gốc repository. Các script tự chuyển về thư mục gốc trước khi chạy Python.

```bash
# Tải PhoBERT-base-v2 và VnCoreNLP một lần; cần Internet.
bash scripts/setup_m0.sh

# Chuẩn bị train/validation; cần processed ViFactCheck có sẵn.
bash scripts/run_m0.sh prepare

# Kiểm tra kỹ thuật: 16 train, 12 validation, 1 epoch, seed 42.
bash scripts/run_m0.sh train --smoke --seed 42

# Huấn luyện M0 một seed trên toàn bộ train, đánh giá toàn bộ validation.
bash scripts/run_m0.sh train --seed 42

# Chạy lần lượt cả ba seed 13, 42, 2026.
# Dùng output khác để tránh trùng run seed_42 đã tạo phía trên.
bash scripts/run_m0.sh train --output-dir outputs/m0_three_seeds
```

Smoke đã có sẵn trong checkout này; nếu muốn chạy lại, dùng thư mục mới:

```bash
bash scripts/run_m0.sh train --smoke --seed 42 --output-dir outputs/m0_smoke_repeat
```

Trainer từ chối ghi đè run đã tồn tại. Nếu run lỗi hoặc muốn chạy lại, chọn output mới. Chưa có resume optimizer từ giữa run. Không dùng thư mục smoke làm checkpoint bắt đầu của run chính thức; mỗi run mới khởi tạo từ PhoBERT đã pin và head phân loại mới theo seed.

Các tuỳ chọn bổ sung:

```bash
bash scripts/run_m0.sh train --help
bash scripts/run_m0.sh train --seed 42 --device cuda
bash scripts/run_m0.sh train --config configs/experiments/m0.yaml --seed 42
```

## Cấu hình và train

Cấu hình: `configs/experiments/m0.yaml`.

| Thành phần | Giá trị |
|---|---|
| Backbone | `vinai/phobert-base-v2`, commit `86cd7fd4c148980922ac11a2cf5e257f2ba639e1` |
| Tách câu | `conservative_vi_v1`, giữ raw text và offset ký tự |
| Tách từ verifier | VnCoreNLP `wseg`, commit `62bbc58fe5d113c898eae112656be97dcf50b3a0` |
| BM25 | Lucene; `k1=1.5`, `b=0.75`; tokenizer `unicode_word_v1`; IDF trong từng context |
| Hòa điểm BM25 | Thứ tự câu tăng dần trước khi cắt top-k |
| K ứng viên / verifier | 20 / 5 |
| Nhãn | `SUPPORTED=0`, `REFUTED=1`, `NOT_ENOUGH_INFO=2` |
| Ngân sách cặp | 256 subword token bao gồm special tokens; claim tối đa 96 |
| Epoch | 3 giai đoạn đầu + 2 tiếp tục; optimizer/scheduler liên tục, không reset giữa hai giai đoạn |
| Optimizer | AdamW, LR thử nghiệm `2e-5`, weight decay `0.01` |
| Batch mặc định | 2 claim/microbatch, accumulation 8; tối đa 16 claim/optimizer step |
| LR schedule | Linear warmup/decay trên tổng số optimizer step, warmup ratio 0.06 |
| Chọn checkpoint | Macro-F1 validation lớn nhất; hòa điểm chọn epoch sớm hơn |
| Seed | 13, 42, 2026 |

Pair budget ưu tiên giữ claim sau khi cắt tối đa 96 token, phần còn lại dành cho một câu evidence. Có thống kê số claim/evidence/pair bị cắt trong log. Câu padding không tồn tại: collator flatten các cặp thật và dùng `bag_index` để nhóm lại theo claim.

Mỗi run xuất:

```text
outputs/m0/seed_42/
    best/                          # Model, tokenizer và label mapping
    run.json                       # Config, seed, versions, source hashes, data manifest, cost
    history.json                   # Loss và validation từng epoch
    validation.predictions.jsonl   # Dự đoán từ checkpoint tốt nhất
    validation.metrics.json        # Verdict và sentence retrieval, coverage, cost
```

Nếu chạy cả ba seed, có thêm `validation.summary.json` với mean/std (sample std, ddof=1). Các kết quả trong vòng đời development vẫn phải ghi rõ trạng thái LR chưa khóa. Thời gian inference gồm collation, tách từ/tokenization và model, không gồm tải model hoặc tạo BM25. Train dùng float32; chưa tối ưu mixed precision. Seed và cấu hình được lưu; không khẳng định bitwise giống nhau trên mọi phần cứng/backend.

## Dự đoán và đánh giá lại

Ví dụ sau áp dụng **sau khi đã hoàn tất run đầy đủ seed 42**:

```bash
bash scripts/run_m0.sh predict \
  --checkpoint outputs/m0/seed_42/best \
  --inputs data/interim/vifactcheck/m0/validation.inputs.jsonl \
  --output outputs/m0/seed_42/validation.reloaded.jsonl

bash scripts/run_m0.sh evaluate \
  --predictions outputs/m0/seed_42/validation.reloaded.jsonl \
  --targets data/interim/vifactcheck/m0/validation.targets.jsonl \
  --inputs data/interim/vifactcheck/m0/validation.inputs.jsonl \
  --output outputs/m0/seed_42/validation.reevaluated.json
```

`predict` không mở target/gold; input chỉ có claim và các câu BM25. Label và gold sentence IDs được ghép bằng ID trong evaluator. Các file prediction lưu sentence IDs, xác suất theo thứ tự S/R/NEI, nhãn dự đoán và seed. File metadata đi kèm lưu checksum input/checkpoint/output và chi phí.

Evaluator báo lỗi nếu thiếu/thừa/trùng ID, xác suất không hợp lệ hoặc nhãn không khớp argmax. Macro-F1 luôn tính trên cả ba lớp, kể cả lớp vắng trong một tập kiểm tra nhỏ.

## Dữ liệu, alignment và pilot

Đầu ra chuẩn bị nằm ở `data/interim/vifactcheck/m0/`:

- `{split}.inputs.jsonl`: claim, context ID, số câu và top-20 ứng viên; không có nhãn/gold.
- `{split}.targets.jsonl`: nhãn claim, gold sentence IDs, trạng thái và chi tiết alignment; chỉ dành cho loss/evaluation.
- `{split}.alignment_review.jsonl`: các trường hợp chưa khớp hoặc mơ hồ.
- `manifest.json`: phiên bản preprocessing, tham số BM25, checksum nguồn/đầu ra.
- `audit.json`: số lượng, phân phối nhãn, overlap context, alignment và pilot.
- `sentence_pilot.jsonl`: 100 context train/validation được chọn theo hash để rà soát.

Snapshot lần triển khai:

| | Train | Validation |
|---|---:|---:|
| Claim | 5.062 | 723 |
| Context phân biệt | 1.035 | 496 |
| Supported + Refuted | 3.409 | 500 |
| Gold khớp chắc chắn | 1.873 | 271 |
| Coverage S/R | 54,94% | 54,20% |

Căn chỉnh chỉ gộp khoảng trắng, giữ nguyên dấu câu/giá trị số/ngày/tháng; cần mỗi snippet có đúng một vị trí khớp. Nhiều vị trí là `ambiguous`; thiếu vị trí là `unmatched`; một phần khớp là `partial`. Một gold snippet có thể phủ nhiều câu. Không lấy điểm số của retriever để quyết định gold đúng ở đâu.

Sentence Hit@5/20, macro Recall@5/20, MRR@5/20 và complete-gold chỉ tính trên S/R căn chỉnh hợp lệ, luôn kèm coverage. NEI không có recall bằng chứng giả định. **Tất cả claim, kể cả NEI hoặc gold chưa khớp, vẫn tham gia train và verdict evaluation.** Coverage còn thấp; chưa suy rộng retrieval metrics trên tập con này thành chất lượng chọn bằng chứng của toàn bộ dataset.

Có 495 context phân biệt của validation xuất hiện trong train. Đây không tự chứng minh rò rỉ nhãn, nhưng split chính thức không đánh giá việc tổng quát hóa sang bài báo hoàn toàn chưa thấy.

Pilot đã qua kiểm tra tự động trên 2.060 câu: offset đúng, không chồng lấn, không mất ký tự ngoài whitespace. Rà soát thủ công đủ 100 context còn chưa hoàn thành; `manual_review_complete` vẫn là `false`.

## Test chính thức sau khi khóa giao thức

Chỉ thực hiện sau khi hoàn tất pilot và chốt thiết lập chung theo Proposal. Chuẩn bị test vào **thư mục riêng** để không thay manifest train/validation:

```bash
bash scripts/run_m0.sh prepare --splits test \
  --output-dir data/interim/vifactcheck/m0_test

bash scripts/run_m0.sh predict \
  --checkpoint outputs/m0/seed_42/best \
  --inputs data/interim/vifactcheck/m0_test/test.inputs.jsonl \
  --output outputs/m0/seed_42/test.predictions.jsonl

bash scripts/run_m0.sh evaluate \
  --predictions outputs/m0/seed_42/test.predictions.jsonl \
  --targets data/interim/vifactcheck/m0_test/test.targets.jsonl \
  --inputs data/interim/vifactcheck/m0_test/test.inputs.jsonl \
  --output outputs/m0/seed_42/test.metrics.json
```

Lặp cho ba seed; không đổi checkpoint theo test. Không chạy các lệnh test trong lần triển khai này.

## Thứ tự đọc code

1. `data/sentences.py`: câu, ID, offset.
2. `retrieval/context_bm25.py`: xếp hạng câu trong context.
3. `data/evidence_alignment.py`, `data/prepare_m0.py`: gold alignment và chuẩn bị dữ liệu.
4. `data/word_segmentation.py`: bridge gọi VnCoreNLP.
5. `training/m0_dataset.py`: chọn top-5, tokenizer, batch và bag_index.
6. `models/verifier.py`: softmax, pooling và claim loss.
7. `training/train_m0.py`, `training/m0_runtime.py`: training, checkpoint, logging.
8. `inference/predict_m0.py`, `evaluation/evaluate_m0.py`: predict và đánh giá tách biệt.

Các đường dẫn module ở trên nằm trong `src/factcheck/`. Chạy kiểm tra bằng `.venv/bin/python -m pytest` và `.venv/bin/python -m ruff check src tests`. Test dùng mô hình nhỏ cục bộ để không cần tải tài nguyên; smoke thực tế sử dụng đúng PhoBERT và VnCoreNLP.
